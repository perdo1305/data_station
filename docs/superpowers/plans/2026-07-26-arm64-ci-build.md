# ARM64 CI Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the slow arm64 compile (colcon workspace + LVGL/rclcpp `ui_runner` UI binary) off the Raspberry Pi and onto a GitHub Actions native arm64 runner, publishing the build output as a release asset the Pi downloads instead of compiling.

**Architecture:** A GitHub Actions workflow (`runs-on: ubuntu-24.04-arm`) checks out the repo, installs ROS2 Jazzy + UI build tooling, runs `colcon build` then `cmake --build` for the UI, tars the two output directories, and publishes them to a fixed-tag (`latest-arm64`) GitHub Release. A Pi-side shell script downloads and extracts that tarball over the Pi's local `install/` and UI build directory.

**Tech Stack:** GitHub Actions (`ubuntu-24.04-arm` hosted runner), ROS2 Jazzy, colcon, CMake, `softprops/action-gh-release`, bash.

## Global Constraints

- Runner: `ubuntu-24.04-arm` (GitHub-hosted native arm64, free for public repos) — exact value, do not substitute a QEMU/`buildx` cross-build approach.
- Trigger: `push` to `master` only (per spec — no `workflow_dispatch`, no PR trigger).
- Release tag is fixed: `latest-arm64`. Every successful build overwrites this same tag's asset — never create per-commit tags/releases.
- `colcon build` must run **without** `--symlink-install` (plain copy build), so `install/` is self-contained and portable to a machine that never ran the build.
- Repo is public (`perdo1305/data_station`) — the Pi's download step must NOT require any GitHub auth token.
- Out of scope: Python pip runtime deps (`python-can`, `cantools`, `gpiod`, Adafruit libs) — unchanged, still installed directly on the Pi.

### Task 1: Add the arm64 build-and-release workflow

**Files:**
- Create: `.github/workflows/build-arm64.yml`

**Interfaces:**
- Produces: a GitHub Release tagged `latest-arm64` carrying asset `lart-dashboard-arm64.tar.gz`, containing `install/` (colcon output) at its root and `LART_Car_Dashboard_v1/build/ui-build/` (containing the `ui_runner` binary) — this exact tarball layout is what Task 2's pull script consumes.

- [ ] **Step 1: Write the workflow file**

```yaml
name: Build ARM64

on:
  push:
    branches: [master]

permissions:
  contents: write

jobs:
  build-arm64:
    runs-on: ubuntu-24.04-arm
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          submodules: recursive

      - name: Add ROS2 apt repository
        run: |
          sudo apt-get update
          sudo apt-get install -y curl gnupg lsb-release
          sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg
          echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
          sudo apt-get update

      - name: Install ROS2 and build tooling
        run: |
          sudo apt-get install -y \
            ros-jazzy-ros-base \
            ros-jazzy-rclcpp \
            ros-jazzy-rclpy \
            ros-jazzy-std-msgs \
            ros-jazzy-rosidl-default-generators \
            ros-jazzy-rosidl-default-runtime \
            python3-colcon-common-extensions \
            build-essential \
            cmake \
            pkg-config \
            libsdl2-dev

      - name: Build ROS2 workspace
        run: |
          source /opt/ros/jazzy/setup.bash
          colcon build

      - name: Build dashboard UI
        run: |
          source /opt/ros/jazzy/setup.bash
          source install/setup.bash
          cmake -S LART_Car_Dashboard_v1/src/ui -B LART_Car_Dashboard_v1/build/ui-build
          cmake --build LART_Car_Dashboard_v1/build/ui-build --parallel

      - name: Package artifact
        run: tar czf lart-dashboard-arm64.tar.gz install LART_Car_Dashboard_v1/build/ui-build

      - name: Publish release
        uses: softprops/action-gh-release@v2
        with:
          tag_name: latest-arm64
          name: "Latest ARM64 build"
          files: lart-dashboard-arm64.tar.gz
```

### Task 2: Add the Pi-side pull script

**Files:**
- Create: `scripts/pull_arm64_build.sh`

**Interfaces:**
- Consumes: release asset `lart-dashboard-arm64.tar.gz` at tag `latest-arm64` on `perdo1305/data_station`, produced by Task 1, with the tarball layout `install/` + `LART_Car_Dashboard_v1/build/ui-build/` at its root.
- Produces: `install/` and `LART_Car_Dashboard_v1/build/ui-build/` populated at the repo root, ready for `source install/setup.bash`.

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
set -euo pipefail

REPO="perdo1305/data_station"
TAG="latest-arm64"
ASSET="lart-dashboard-arm64.tar.gz"
WS_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"

TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT

echo "Downloading ${ASSET} from ${REPO}@${TAG}..."
curl -fsSL "https://github.com/${REPO}/releases/download/${TAG}/${ASSET}" -o "$TMP/${ASSET}"

echo "Removing old build output..."
rm -rf "$WS_DIR/install" "$WS_DIR/LART_Car_Dashboard_v1/build/ui-build"

echo "Extracting into ${WS_DIR}..."
tar xzf "$TMP/${ASSET}" -C "$WS_DIR"

echo "Done. Run: source $WS_DIR/install/setup.bash"
```

- [ ] **Step 2: Make it executable**

Run: `chmod +x scripts/pull_arm64_build.sh`

- [ ] **Step 3: Verify script syntax**

Run: `bash -n scripts/pull_arm64_build.sh && echo OK`
Expected: `OK`

- [ ] **Step 4: Commit**

